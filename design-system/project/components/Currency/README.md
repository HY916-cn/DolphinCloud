# Currency

后台“货币”页、货币登记表单，以及总览顶部的经营看板。规则见 PHASE-2 §11、§16.2，函数名、字段和错误码以后端交接为准：

- `currency_overview()`：纸币、电子币和兑付能力。
- `currency_moves` 表：登记记录。
- `record_currency(...)`：登记。
- `dashboard()`：经营看板。

财务、行长、银行管理员能看“货币”页和经营看板，只有银行管理员能登记。

导航图标 `coin`，两个字“货币”，排在“轧账”后面，侧边导航和手机“全部功能”里都有；页面标题“货币”。

## 写法

- 张数写“30 张”，表格里只写数字，列名写单位。金额经 `lib/format.ts` 格式化，单位 HTB。负数用 −，如“−12”“−36 HTB”。
- 面额写“5 元”“10 元”，按从小到大排列。一笔登记的各面额写成“5 元 × 10、10 元 × 30”，张数为 0 的面额不写；更正的张数带符号，如“5 元 −2、10 元 +1”。
- 兑付能力写百分数，保留 1 位小数，如“25.3%”；提示线写整数，如“30%”。
- 日期写“12月7日”，时间写“12月7日 09:00”。
- 登记的种类：

| 代码 | 名称 | 图标 |
| --- | --- | --- |
| `baseline` | 期初现金 | `balance` |
| `issue` | 发行 | `coin` |
| `recover` | 回收 | `back` |
| `destroy` | 销毁 | `close` |
| `correction` | 更正 | `passbook` |

## “货币”页

从上到下排成一列。电脑上“电子币”的两张卡片并排，其余同手机。

### 页头

右边是页面主操作“登记”：图标 `plus`，`dc-btn-primary dc-btn-sm`，只给银行管理员。手机上主操作放进 `ActionBar`。点开是单独的页面“登记货币”（见下面）。

### 提示

- 还没有登记期初现金（`baseline` 为 `null`）时，`Notice`（默认，`warning` 图标）放在页面最上面：
  - 标题：“先登记银行期初现金”。
  - 银行管理员看到的说明：“登记金库和各储蓄盒现有的各面额张数，从登记那一刻起计算银行应有现金。现在按全部流水计算。”
  - 财务、行长看到的说明：“由银行管理员登记。现在按全部流水计算。”
- 兑付能力低于提示线（`payout.low`）时，`Notice`（`danger`）：
  - 标题：“兑付能力 25.3%，低于 30%”。
  - 说明：“银行应有现金 1,480 HTB，是账户余额合计 5,850 HTB 的 25.3%。”

### 兑付能力

`Stats` 三项：

| 名称 | 数值 | `em` |
| --- | --- | --- |
| 兑付能力 | “25.3%” | 低于提示线时 `is-danger`“低于提示线 30%”，其他写“提示线 30%” |
| 银行应有现金 | “1,480 HTB”，即 `paper.bank` | 不写 |
| 账户余额合计 | “5,850 HTB”，即 `electronic.total` | 不写 |

账户余额合计为 0（`ratio` 为 `null`）时，兑付能力写“—”，`em` 写“账户余额合计为 0”，不提示。

### 纸币

标题 `heading is-section`“纸币”，下面一张 `dc-card dc-stack`。

1. `SummaryList`，金额取 `paper`：
   - 期初现金、发行、回收（写“−120 HTB”）、销毁（写“−20 HTB”）、流水的现金变动（带符号，如“+2,310 HTB”）。
   - `is-total` 一行：银行应有现金。
   - 最后一行：流到学生手中。为负时下面 `caption`：“学生把上线前就拿着的纸币存了进来。”
2. 按面额的 `DataTable`，`notes` 每个面额一行。
   - 列（张）：面额、期初、发行、回收、销毁、流水、银行应有、储蓄盒实点、流到学生手中。
   - “流水”和“流到学生手中”带符号。
   - `tfoot` 一行“合计（HTB）”，各列写 `paper` 的金额，“储蓄盒实点”写 `counted.total`。
   - 储蓄盒实点和银行应有不同时，那一格加 `is-danger`。这是提醒去对账，不表示出错。
   - `counted` 为 `null` 的面额，实点那一格写“—”。
3. 表下 `caption`，写储蓄盒实点的来源：
   - 一般写：“储蓄盒实点：3 个储蓄盒最近一次轧账的实点，不含金库，最晚 12月4日 16:20。”
   - 还没有轧账的实点时写：“还没有储蓄盒的实点。”

手机上表格自己横向滚动，页面不横向滚动。

### 电子币

标题 `heading is-section`“电子币”，下面两张 `dc-card`，各放一个 `SummaryList`：

- **账户余额合计**：活期、定期、理财本金；`is-total` 一行“账户余额合计”。
- **电子币新增**：标题下 `caption`“从登记期初现金起；没有登记时从头算。”各行带符号：
  - 工资、利息、理财盈亏（写“+12 HTB”或“−3 HTB”，数不上色）。
  - 放款（“+300 HTB”）、还款（“−180 HTB”）。
  - `is-total` 一行“电子币新增”。

### 登记记录

标题 `heading is-section`“登记记录”，从新到旧，全部列出。没有记录时 `EmptyState`“还没有登记”。

`dc-list`，每笔一行 `dc-list-item`。左边先放 `dc-list-icon`（种类的图标），再放三行文字：

- 第一行：种类名称，后接批次号或对应的登记，如“发行 FX-1”“期初现金”“更正 · 对应 发行 FX-1”；行尾 `b` 写合计“350 HTB”，更正带符号。
- 第二行 `small`：日期和各面额，如“12月7日 · 5 元 × 10、10 元 × 30”。
- 第三行 `small`：用途或原因、审批人、登记人和时间，如“开学发行 · 审批 王老师 · 银行管理员 12月7日 09:00 登记”。没有的项不写。

被更正过的登记，右边加 `dc-tag`“有更正”。

刚登记的一行加 `is-new`。

### 读不到

- `currency_overview()` 读取中：`Stats`、纸币、电子币显示 `Skeleton`。
- 读取失败：`Notice`（`danger`）“暂时无法读取货币数据”“请检查网络后重试。”，加“重试”按钮。不显示 0。
- 登记记录单独读取，失败时只在那一节提示。

## 登记货币

单独的页面，标题“登记货币”，返回“货币”页。只有银行管理员能打开。

打开时生成登记的 id（`crypto.randomUUID()`），这次填写中重复提交都用它。

### 选择种类

`ChoiceCard` 横排四项：发行、回收、销毁、更正。

还没有登记期初现金时，最前面加“期初现金”，并默认选中它。登记过期初现金后，默认选“发行”。

| 种类 | 选项说明 |
| --- | --- |
| 期初现金 | 金库和储蓄盒现有的 |
| 发行 | 新的纸币开始流通 |
| 回收 | 从银行现金里取出 |
| 销毁 | 损毁的纸币 |
| 更正 | 冲抵登错的一笔 |

### 表单

种类下面一张 `dc-card dc-stack`。各项从上到下：

| 项 | 期初现金 | 发行 | 回收 | 销毁 | 更正 |
| --- | --- | --- | --- | --- | --- |
| 对应的登记（`Select`） | | | | | 必填 |
| 批次号（`Field`，1～40 字） | | 必填 | | | |
| 日期（`DatePicker`，默认今天，不能晚于今天） | 必填 | 必填 | 必填 | 必填 | |
| 各面额张数 | 必填 | 必填 | 必填 | 必填 | 必填 |
| 用途或原因（多行 `Field`，最多 100 字） | 可不写 | 必填，名称写“用途” | 必填 | 必填 | 必填 |
| 审批人（`Field`，1～40 字） | | 必填 | | | |

- **对应的登记**：列出不是更正的登记，新的在上，如“发行 FX-1 · 12月7日 · 350 HTB”。
- **各面额张数**：`QtyStepper` 面额卡，`dc-denoms` 不加业务色，写法同备用金；每张卡的 `dc-qty-sum` 写小计。
  - 期初现金、发行、回收、销毁：每项 0～100000 张。
  - 更正：每项 −100000～100000 张，减按钮在 0 以下仍可用；张数为负时小计写“−10 HTB”。
- **合计**：面额下面 `SummaryList` 一行 `is-total`，如“发行合计 350 HTB”。

各种类在卡片最上面放一行 `caption`：

| 种类 | `caption` |
| --- | --- |
| 期初现金 | “银行现有的全部纸币：金库加各储蓄盒。上线当天开门营业前登记，只登记一次。” |
| 回收 | “从银行现金里取出，不再流通，如旧版回收。” |
| 销毁 | “损毁、不再流通的纸币。” |
| 更正 | “多登的面额写负数，少登的写正数，合计可以为 0。记在今天。” |

`ActionBar`：次按钮“取消”（回到“货币”页），主按钮“登记”，合计写“发行 350 HTB”。

“登记”在以下情况禁用：

- 必填项没填。
- 张数全为 0。
- 合计超过 10,000,000 HTB。
- 合计为 0（更正除外）。

### 确认登记

`ConfirmSheet`。

**标题**：

- 期初现金、回收、销毁：“登记期初现金 1,200 HTB？”“登记回收 120 HTB？”
- 发行：“登记发行 FX-1，350 HTB？”
- 更正：“登记更正 −10 HTB？”

**列表**：`SummaryList` 逐项列出：

- 日期、各面额。
- 批次号、用途或原因、审批人，没有的项不写。
- 更正写“对应：发行 FX-1”。

**说明**：“登记后不能修改，登错了再登一笔更正。”

**主按钮**：“确认登记”。

确认后调用 `record_currency`。成功后回到“货币”页，`Toast`“已登记”，新的一行加 `is-new`。

### 没有登记成功

服务器拒绝时，弹层关闭，表单保留填写的内容。

字段的错误写在那一项 `Field` 上（`is-error`）：

| 错误 | 提示 |
| --- | --- |
| `INVALID_INPUT`，`on_date` | “日期不能晚于今天。” |
| `INVALID_INPUT`，`reason` | “请写明用途，最多 100 字。”（其他种类写“原因”） |
| `INVALID_INPUT`，`batch_no` | “批次号 1～40 字。” |
| `INVALID_INPUT`，`approver_name` | “请写审批人，最多 40 字。” |
| `ALREADY_EXISTS`，`batch_no` | “批次号 FX-1 已经用过。” |

其他错误用 `Notice`（`danger`），写在种类上面：

| 错误 | 标题 | 说明 |
| --- | --- | --- |
| `INVALID_AMOUNT`，带 `denomination` | “更正后 5 元会少于 0 张” | “这笔登记加上它的全部更正，每种面额都不能少于 0 张。” |
| `INVALID_AMOUNT`，其他 | “张数不对” | 期初现金、发行、回收、销毁：“每种面额 0～100000 张，合计不超过 10,000,000 HTB，不能为 0。”；更正：“每种面额 −100000～100000 张，不能全为 0。” |
| `ALREADY_EXISTS`，`kind` | “期初现金已经登记过” | “期初现金只登记一次，登错了请登一笔更正。”同时重新读取，种类里去掉“期初现金” |
| `INVALID_INPUT`，`corrects` | “不能更正这笔登记” | “只能对应一笔不是更正的登记，请重新选择。” |
| `INVALID_INPUT`，`id` 或 `kind` | “没有登记” | “请返回货币页后重新打开。” |

## 经营看板（总览）

财务、行长、银行管理员的总览最上面是经营看板，取自 `dashboard()`。

### 六个数

`Stats` 六项（`data-n="6"`）：

| 名称 | 数值 | `em` |
| --- | --- | --- |
| 账户余额 | `balance.total`，HTB | “含定期、理财本金” |
| 银行应有现金 | `bank_cash`，HTB | “兑付能力 25.3%”；低于提示线时加 `is-danger`，写“兑付能力 25.3%，低于 30%”；`ratio` 为 `null` 时不写 |
| 贷款余额 | `loans.remaining`，HTB | 有逾期时 `is-danger`“逾期 2 笔 · 45 HTB”；没有时写“12 笔未结清”；没有贷款时不写 |
| 文创库存 | `stock.qty`，件 | “成本 1,234 HTB”；有没填成本的商品时接“ · 2 种没填成本” |
| 本周业务 | `week.count`，笔 | 和上周（`weeks` 倒数第二项）比：`is-up`“比上周 +12%”、`is-down`“比上周 −5%”；上周为 0 时写“上周 0 笔”；相同时写“和上周持平” |
| 本周锚点 | `anchor.anchor`，如“2.25%” | “11月16日公布”；`week_start` 为空时写“还没有公布，按初始锚点” |

“银行应有现金”这一格整格是到“货币”页的链接：

- 写成 `<a class="dc-card dc-stat">`，悬停时描边变 `dolphin`，键盘聚焦时出现 `focus-ring`。
- 低于提示线时整格再加 `is-danger`，描边换成 `danger`。
- `em` 放不下时可以折行。

### 每周业务

六个数下面一张 `dc-card`，放 `Chart` 的柱状图：

- `figcaption`“每周业务笔数”，`small` 写“最近 12 周”。
- 12 根柱子，从早到晚，海豚蓝。
- 横轴隔一周写一个标签，共 6 个，最后一个是本周，写成“11/16”。
- `data-tip`“11月16日起 · 128 笔”。
- `aria-label` 写出 12 周的全部数字。

图下右边 `dc-btn-ghost dc-btn-sm`“各周数字”，打开 `Sheet`“每周业务笔数”。`Sheet` 里是 `DataTable`，列为“周一”和“笔数”，新的在上。

### 读不到

- 读取中：六格和图显示 `Skeleton`。
- 读取失败：`Notice`（`danger`）“暂时无法读取经营看板”“请检查网络后重试。”，加“重试”按钮。不显示 0。

使用者提供：`currency_overview()`、`currency_moves`、`dashboard()` 的数据，当前身份，以及面额列表。

动效：登记后回到列表，新的一行加 `is-new`；`Stats` 随页面 `dc-enter` 进入，数字不滚动；确认弹层同 `Sheet`；减少动态效果时直接显示结果。
