# RiskAlerts

后台“风险提醒”：系统在大额贷款、大额取款、频繁冲正、改参数等情况下记一条提醒（PHASE-2 §12），行长和银行管理员查看，标为“已查看”，或“终止”这件事。财务和其他身份看不到这一页和总览里的这一节。

导航图标 `warning`，两个字“风险”，排在“轧账”后面，侧边导航和手机“全部功能”里都有；页面标题“风险提醒”。

## 种类

每种提醒有固定的名称和图标，列表、筛选和详情都用这一套：

| 代码 | 名称 | 图标 | 对象 | 能否终止 |
| --- | --- | --- | --- | --- |
| `loan_large` | 大额贷款 | `loan` | 学生 | 能，提前到期 |
| `loan_overdue` | 贷款逾期 | `loan` | 学生 | 能，提前到期 |
| `withdraw_large` | 大额取款 | `withdraw` | 学生 | 能，冲正这笔取款 |
| `term_early` | 提前支取 | `savings` | 学生 | 能，冲正这笔提前支取 |
| `reversal_many` | 冲正过多 | `back` | 柜员 | 能，强制该柜员下班 |
| `ops_frequent` | 频繁操作 | `clock` | 学生 | 能，强制经办柜员下班 |
| `setting_change` | 参数修改 | `settings` | 参数 | 能，恢复到修改前的值 |
| `credit_adjust` | 信用分调整 | `gauge` | 学生 | 能，记一条相反的变动 |
| `stock_low` | 库存不足 | `inbox` | 商品 | 只能“已查看” |
| `cash_unbalanced` | 轧账不平 | `balance` | 柜员 | 只能“已查看” |
| `manual_entry` | 补录流水 | `passbook` | 学生 | 只能“已查看” |
| `txn_correct` | 编辑流水 | `passbook` | 学生 | 只能“已查看” |
| `credit_switch` | 信用分开关 | `gauge` | 全部学生 | 只能“已查看” |

能否终止以每条提醒的 `terminable` 为准。

## 一行提醒

列表页和总览用同一种行：`dc-list` 里的 `dc-list-link`，整行链接到这条提醒的页面。

- 左边 `dc-list-icon`，种类的图标。
- 中间第一行：“名称 · 对象”，如“大额取款 · 张小明”“冲正过多 · 柜员小林”“参数修改 · 取款限额”“库存不足 · 海豚书签”“信用分开关 · 全部学生”，后面接状态标签（见下表）。
- 第二行 `small`：时间“12月4日 10:20”，后接说明（见下表），频繁操作、大额取款、提前支取等柜台业务再接“· 柜员小林”。
- 已处理的第三行 `small`：“王老师 12月4日 11:05 查看”或“王老师 12月4日 11:05 终止：学生说明了用途”，可以折行。
- 最右边是右箭头。

状态标签：

| 状态 | 标签 |
| --- | --- |
| 未处理 | `dc-tag-pending`，`clock` 图标，“未处理” |
| 已查看 | `dc-tag`，`check` 图标，“已查看” |
| 已终止 | `dc-tag`，`close` 图标，“已终止” |

### 说明

按 `detail` 拼写，金额经 `lib/format.ts` 格式化，单位 HTB；数不上色。

| 种类 | 说明 |
| --- | --- |
| 大额贷款 | “贷款 120 HTB，超过 50 HTB”；放款时信用分低于线时写“放款时信用分 580，低于 600”，两条都满足时用“；”连起来 |
| 贷款逾期 | “第 2 期逾期，剩余本金 98 HTB” |
| 大额取款 | “取款 90 HTB，超过单笔限额 100 HTB 的 80%” |
| 提前支取 | “提前支取本金 100 HTB 的定期，取出 100.4 HTB” |
| 冲正过多 | “当天第 3 笔冲正，原流水 HT20261204…” |
| 频繁操作 | “10 分钟内在柜台办理 5 笔” |
| 参数修改 | 单个值：“从 100 HTB 改为 150 HTB”；整组的参数（利率、信用分、理财、风险提醒、工资标准）：“改了 2 项”，逐项写在提醒页里 |
| 信用分调整 | “加 20 分，调整后 650 分”或“减 20 分，调整后 610 分” |
| 库存不足 | “库存 3 件，安全库存 5 件” |
| 轧账不平 | 柜员下班时：“下班时柜员点的现金少 2 HTB”；复核时：“复核时点的现金多 1 HTB”；金额相等、面额不同写“面额不对” |
| 补录流水 | “补录存款 20 HTB，发生于 11月3日 10:00” |
| 编辑流水 | “编辑流水 HT20261204…，改为存款 20 HTB” |
| 信用分开关 | “暂停信用分，涉及 320 位学生”或“重新开启信用分，涉及 320 位学生” |

参数名用参数页上的名称（“取款限额”“定期周利率”“风险提醒”“工资标准”……），参数页没有的写原来的 key。

## 后台“风险提醒”页

- 上方 `FilterBar`，没有搜索框：日期行“从”“到”（提醒的日期，上海时间，默认不限）；种类行 `FilterChips`（13 种，可多选），右边“清除条件”。
- 下面 `Tabs` 按状态：未处理（默认，带条数，取自 `risk_alert_overview().open`）、已查看、已终止、全部。
- 列表从新到旧，按日期分组：每组 `dc-list-title`“12月4日 周五”，下面一组 `dc-list`。这一页的组里行数不限。
- 每次取 50 条；还有更早的时，最下面 `dc-btn-secondary`“更早的提醒”，把这一页最后一条的 `id` 作为 `p_before` 接着取，接在后面。
- 没有记录时 `EmptyState`：未处理“没有未处理的风险提醒”，其他“没有符合条件的风险提醒”。
- 处理完回到列表时保留原来的筛选，处理过的那一行加 `is-new`。

## 提醒页

单独的页面，标题是种类名称，副标题是对象（“大额取款”“张小明”），返回到风险提醒页。从总览点进来的，返回到总览。

**电脑（≥1024px）**用 `dc-split`：左栏“这条提醒”，右栏 `is-sticky` 的“处理”。**手机和平板**排成一列，“处理”在下。

“这条提醒”（`dc-card`）是 `SummaryList`：

1. 时间“12月4日 10:20”、种类、状态标签。
2. 对象：学生“张小明 · 五年级 2 班 · s1”，柜员“柜员小林”，商品名，参数名。
3. 说明的各项拆成单独的行，例如大额取款：流水号、取款金额“90 HTB”、单笔限额“100 HTB”、提醒线“80%”、经办柜员；参数修改：逐项写“修改前”“修改后”，整组的参数只列改了的那几项，如“初始锚点：2% → 2.5%”；轧账不平：差额（`is-danger`）、各面额差几张、当时写的原因；补录、编辑、信用分调整、信用分开关：原因。
4. 已处理的加：处理“王老师 12月4日 11:05 终止”，处理说明。
5. 贷款的两种下面放 `dc-btn-ghost dc-btn-sm`“查看贷款”，到贷款详情；轧账不平的放“查看这次上班”，到轧账的复核页。

“处理”（`dc-card`，标题 `heading`“处理”），只有未处理的才有：

- 说明：多行 `Field`，最多 200 字，提示“已查看可以不写；终止时写清原因”。
- 能终止的：下面 `caption` 写终止会做什么，同确认弹层的说明。
- 只能已查看的：`caption`“这种提醒只能标为已查看。”
- 页面主操作放进 `ActionBar`（`dc-actions is-row`）：能终止的先 `dc-btn-ghost is-danger`“终止”，再主按钮“已查看”；只能已查看的只有“已查看”。
- 已查看：直接 `handle_alert(id, 'seen', 说明)`，成功后回到列表，`Toast`“已标为已查看”。
- 终止：说明为空时 `Field` 进入 `is-error`，提示“请写明终止的原因”；写好后打开 `ConfirmSheet`，主按钮“确认终止”，确认后 `handle_alert(id, 'terminate', 说明)`。成功后回到列表，`Toast`“已终止”。

已处理的提醒没有“处理”卡片和 `ActionBar`。

### 确认终止

| 种类 | 标题 | 说明 |
| --- | --- | --- |
| 大额贷款、贷款逾期 | “终止张小明的贷款？” | “剩余本金和已产生的利息立即全部到期：先从活期扣，不够的部分算逾期。” |
| 大额取款 | “冲正张小明这笔 90 HTB 的取款？” | “张小明的活期加回 90 HTB，这笔现金不计入任何一次上班。冲正原因记为“其他：<终止原因>”。” |
| 提前支取 | “冲正张小明这笔提前支取？” | “定期恢复为未到期，取出的 100.4 HTB 从活期扣回；活期不够时不能冲正。” |
| 冲正过多、频繁操作 | “让柜员小林强制下班？” | “结束柜员小林这笔业务时的那次上班，柜台马上不能再办理业务，要重新上班才能继续。这次上班没有柜员实点，由财务点数复核。” |
| 参数修改 | “把取款限额恢复为修改前的值？” | “取款限额恢复为 100 HTB，从下一次计算起生效。”整组的参数写“定期周利率恢复为修改前的 5 项值”，逐项列在 `dc-sheet-list` 里 |
| 信用分调整 | “撤回这次信用分调整？” | “再记一条相反的变动：张小明的信用分减 20 分，原因记为“风险提醒终止：<终止原因>”。” |

### 没有处理成功

服务器拒绝时，`Notice`（`danger`）写在“处理”卡片的最上面，提醒仍是未处理：

- `ALERT_HANDLED`：“这条提醒已处理”“王老师 已于 12月4日 11:05 标为已查看。”已终止的写“……已于 12月4日 11:05 终止。”页面重新读取，换成只读。
- `ALERT_OUTDATED`：“参数之后又改过”“这项参数在提醒之后又改过，请先终止后来的那条提醒，或到参数页直接修改。”
- 撤销本身的错误，标题都写“没有终止”，说明用 `errors.ts` 里这个错误码已有的说明，末尾接“可以改为已查看。”：`REVERSAL_NOT_ALLOWED`、`REVERSAL_INSUFFICIENT_BALANCE`、`CREDIT_DISABLED`、`INVALID_INPUT` 的 `loan_id`（贷款已结清或作废）；`duty_id` 带 status 写“这位柜员已经下班了。可以改为已查看。”
- `INVALID_INPUT`：`note`“请写明终止的原因，最多 200 字。”；`action` 带 kind“这种提醒只能标为已查看。”；`id`“找不到这条提醒，请刷新后再试。”

## 总览

行长、银行管理员的总览在经营看板下面放一节“未处理的风险提醒”，写法同“待复核的轧账”：

- `dc-section-head`：标题（`heading`）“未处理的风险提醒 · 3 条”，右边 `dc-btn-ghost dc-btn-sm`“去处理”，到风险提醒页（未处理）。
- 下面 `dc-list`，`risk_alert_overview().recent` 的最多 5 行，行的写法同上（都是未处理，状态标签照写）。点一行打开这条提醒。
- 没有未处理的时整节不显示。读不到时整节不显示，不显示 0。

使用者提供：提醒的种类、对象、时间、`detail`、状态、处理人、处理时间、处理说明、`terminable`。

动效：处理后回到列表，那一行加 `is-new`；确认弹层同 `Sheet`；减少动态效果时直接显示结果。
