# Attendance

考勤：柜员上下班和老师审核班次用的一组部件，用“中”“下”两个字的小标记表示中午班和下午班。

- 班次标记 `<i class="dc-shift is-confirmed">中</i>`，六种状态：`is-confirmed` 有效（`success` 实底）、`is-pending` 待审（白底 `dolphin-deep` 描边）、`is-rejected` 未通过（柜员的班次审查未通过，`danger-soft` 底加删除线）、`is-void` 已作废（登记的班次被作废，白底 `line-strong` 描边、`ink-muted` 字加删除线）、`is-none` 未上班（`cloud-100` 底）、`is-open` 可签到（还没有记录、现在能点的班次：白底、`dolphin` 蓝色虚线框）。旁边总有文字或读屏文字，图例用 `dc-shift-legend` 列出这一页会出现的状态；“可签到”只在能签到的页面列出。
- 周选择 `dc-weekbar`：上一周、日期（`DatePicker is-bare`）、下一周，不在本周时多一个“本周”。页面主操作不放在这里，手机上放进 `ActionBar`。
- 上下班卡片 `dc-duty`：`dc-duty-main` 里 `<b>` 写状态、`<small>` 写一句说明，按钮放右边（多个时用 `dc-duty-actions`）。四种状态：
  - 未上班：“未上班”，说明两个班次的分界，主按钮“上班”。
  - 已上班：“已上班 · 11月10日 07:45 起”，说明现在的班次和下班前要打印总结，次按钮“下班”。
  - 跨天未下班 `is-stale`：进行中的上班开始于上海时间今天以前。写“上次上班还没下班”，说明前加 `warning` 图标：“从 11月9日 07:45 开始，已经跨天。先下班，再重新上班。”，描边和说明用 `danger`，主按钮“下班”，走原来的下班流程。这时柜台不进入搜索，存款、取款、兑换、冲正都不能办理；离线登记的存款照常。
  - 读不到上班状态：`Notice`（`danger`）“暂时无法确认上班状态”，加“重试”。
- 上班先登记备用金：点“上班”后，卡片下方展开一张 `dc-card`，标题（`heading`）“登记备用金”，说明“储蓄盒里现有的零钱。默认是上次下班时点出的张数，复核改过的按复核的数；按实际张数修改，没有就填 0。”。下班点钞与轧账见 `CashCount`。
  - 内容：`QtyStepper` 面额卡，`dc-denoms` 不加业务色，因为备用金不是一笔业务；下面 `SummaryList` 一行 `is-total`“备用金合计 60 HTB”。
  - 按钮：次按钮“取消”、主按钮“确认上班”；手机上放进 `ActionBar`（`dc-actions is-row`）。办理页整页只有 `EmptyState`“未上班”时，这张卡片替换它。
  - 读取默认张数时，面额卡显示 `Skeleton`；没有记录时全部填 0，不另提示；读取失败时全部填 0，并用 `Notice`（默认）说明“没有读到上次下班的张数，已全部填 0”。
  - 服务器拒绝（`INVALID_AMOUNT`）时，用 `Notice`（`danger`）提示“备用金张数有误”“每种面额填 0 或正整数。”，卡片保持展开。
- 办理页在未上班和跨天未下班时，整页只有这张卡片，放大成 `EmptyState`：未上班用 `clock` 图标；跨天未下班用 `warning` 图标并加 `dc-empty-icon is-danger`（`danger-soft` 底、`danger` 图标），按钮是主按钮“下班”。
- 办理中服务器拒绝为跨天未下班（`STALE_DUTY`）时，用 `Notice`（`danger`）提示，结束这次办理后回到上面的整页卡片。
- 单个班次一行 `dc-shift-row`，内容放 `dc-shift-main`。
- 周表：`DataTable` 再加 `dc-week`，今天的列加 `is-today`，单元格里 `dc-week-marks` 放两个班次，可操作的是 `<button class="dc-week-btn">`，只读的是 `<span class="dc-week-btn">`。两者都没有外框，只显示里面的班次标记：能点的空班次用 `is-open` 的虚线框表示，悬停时格子变 `cloud-100` 底，键盘聚焦时出现 `focus-ring`；柜员自己的一周用 `dc-week-cell`（标记加文字）。`dc-week-btn` 是 32×36px，属于电脑表格内密集控件的例外。

## 全员考勤

- 柜员、财务、库管、行长参与考勤，银行管理员和运维员不参与。柜员按柜台上班、下班自动记班次；财务、库管、行长在自己的“我的”页签到（见 `SettingsPage`）。这两种都是待审，由银行管理员审查。
- 后台考勤页要简洁，只有三样，从上到下：
  1. 周选择 `dc-weekbar`。
  2. 一张 `dc-card`，里面是全员的周表（`dc-table dc-week`）和表下的图例 `dc-shift-legend`。
  3. 银行管理员的 `ActionBar`：“全部确认 3”和“发放工资”。
  
  页面上不放统计卡片，也不放“参与考勤”的开关（开关在人员页）。
- 周表的写法：
  - 所有人在同一张表里，按身份分组：柜员、财务、库管、行长。每组前一行 `tr.is-group`，里面 `th scope="rowgroup"` 横跨整行，写身份名称。组里一人一行；没有人的组不显示。
  - 列：姓名、周一到周日（`th` 写“周一”，`small` 写日期）、有效（班次数）、工资（HTB）。
  - 姓名一格只写姓名；银行管理员看到的姓名是到人员页的链接。没有绑定工资账户的人，姓名下面 `small`“未绑定工资账户”，这一行不能签到。
  - `tfoot` 一行“合计”：全表的有效班次数和工资。
- 发放工资前还有待审班次时，“发放工资”禁用，周选择下面一行 `dc-caption`：“截至 11月22日 还有 3 个待审班次，全部审查后才能发放工资。”其他时候不写。
- 还没有人参与考勤时，表格的位置放 `Notice`：标题“还没有参与考勤的人员”；说明给银行管理员写“在「人员」里打开「参与考勤」。”，给行长写“由银行管理员在「人员」里打开。”
- 点格子签到：行长和银行管理员点周表里还没有记录的那一格（`dc-week-btn`），给那个人签那一个班次，柜员和其他身份一样，签上即有效，不再审查（`makeup_attendance`）。
  - 能点的格子：今天已经开始的班次（13:30 前只有中午班）和以前的日子，标记用 `is-open`（虚线框，`aria-label`“王小林 11月16日 中午班，可签到”）。以后的班次、自己那一行、行长看行长那一行、未绑定工资账户的人都是只读的 `<span class="dc-week-btn">`，标记用 `is-none`。
  - 点了打开 `ConfirmSheet`“给王小林签到？”，说明“11月16日 中午班，签上即有效，计入工资。”，下面说明（多行 `Field`，必填，最多 100 字，提示“例如：值周检查、补记柜台班次”），按钮“取消”“签到”。服务器拒绝时写在弹层里，弹层不关：`ATTENDANCE_OFF` 标题“还没有参与考勤”，说明“请先为王小林开启参与考勤，再签到。”（开关在人员页）。成功后 `Toast`“已签到”，那一格变成有效，`aria-label` 带上说明。
  - 页面上没有单独的“登记班次”按钮。
- 作废：行长和银行管理员点一个有效、还没发工资的班次（柜员的也一样），打开 `ConfirmSheet`“作废王小林 11月16日的中午班？”，说明“作废后这个班次不计工资，不能恢复。”，写原因（必填），按钮“取消”“作废”（`void_attendance`）。作废后那一格显示 `is-void`，文字“已作废”。能不能作废同签到：自己的、行长对行长的不能。
- 待审的班次只有银行管理员能审查（有效 / 未通过），页面主操作“全部确认”“发放工资”也只给银行管理员；行长看到的待审格子是只读的。
- “参与考勤”开关在人员页，只有银行管理员能操作，只对柜员、财务、库管、行长显示，说明“开启后，柜员上班时自动记班次，其他身份在「我的」里签到。”；没有绑定工资账户的人先绑定。
- 服务器拒绝时写在弹层里：
  - `SELF_SERVICE_FORBIDDEN`：“不能给自己签到”，说明“行长的班次由银行管理员签到。”（作废时同样）
  - `INVALID_INPUT`（`id`，作废时）：“待审的班次请审查。”
  - `INVALID_INPUT`（`user_id`）：“银行管理员和运维员不参与考勤。”
  - `ATTENDANCE_PAID`：“已经发过工资”，说明“这个班次的工资已经发放，不能作废。”
  - `ATTENDANCE_REVIEWED`：“已经作废”，说明“这个班次已经作废。”
  - `ALREADY_EXISTS`：“这个班次已经有记录。”

使用者提供：每个班次的状态和完整的 `aria-label`（“小林 10月27日 中午班待审”）。

动效：无。
