# ManualEntry

手动补录与更正流水：系统故障等情况下的备用方案，只有银行管理员能用。后台“流水”页的“补录”和流水详情里的“编辑”，以及补录、编辑生成的流水在各处怎么显示。规则见 PHASE-2 §10.11、§16.2、§16.3；函数名、字段和错误码以后端交接为准。

- 补录：`manual_entry`，类型是存款、取款、兑换、调账四种，记在原始发生时间。
- 编辑：`correct_txn`，系统冲正原流水，再按改好的内容记一笔新流水，两笔都记在原流水的时间，互相关联，原流水保留。
- 之后已经算过的活期利息随之更正，差额在下次结息时入账；涉及现金的补录不计入任何柜员的上班现金。
- 行长、财务和其他身份看不到“补录”和“编辑”。

## 写法

- 补录、编辑生成的流水（`entered_at` 不为空）按原始时间排在列表里。时间那一行写原始时间，后面接“ · 11月15日 补录”（录入日期）：“11月12日 14:20 · 11月15日 补录”。学生明细、存折、柜台查询、后台流水都这样写，不另加标签。
- 标题后半句取流水的说明：补录的“存款 · 补录：系统故障，当天未记”；编辑生成的新流水“存款 · 更正：金额录错”；编辑生成的冲正“冲正 · 金额录错”。
- 存折的交易记录里，补录日期接在摘要后面的小字里：“存款 · 补录：系统故障”下面 `small`“11月15日 补录”。
- 调账 `adjust`：只动活期，不涉及现金。增加时图标 `deposit`、`dc-kind-save`，金额“+20”加 `is-in`，下面写“调账”；减少时图标 `withdraw`、`dc-kind-withdraw`，金额“−20”加 `is-out`，下面写“调账”。
- 活期利息流水的说明里带“含更正”的（“11月10日至11月16日活期利息，含更正 +0.15 HTB”“活期利息更正 +1.20 HTB”）直接显示，不另加说明。
- 学生首页“攒着的利息”更正后可能暂时为负，写“−0.12 HTB”，下面 `small`“之前的利息有更正，之后的利息先补上这部分”。

## 后台流水详情

详情 `SummaryList` 在原有各行之外：

| 情况 | 加的行 |
| --- | --- |
| 补录或编辑生成（`entered_at` 不为空） | “补录”：“11月15日 09:30 由王老师补录”；“办理后余额”的值后面 `small`“录入时的余额” |
| 已被编辑的原流水 | “已更正为”：新流水的交易号，链接，点过去展开那一笔 |
| 编辑生成的新流水（`corrects`） | “更正自”：原流水的交易号，链接 |
| 编辑生成的冲正 | “状态”写“编辑时冲正” |

- 链接写在 `dd` 里的 `<a>`，`dolphin-deep` 加粗，悬停下划线，有焦点环（同 `DataTable` 里的链接）。
- 柜台查询（`student_txns`）同样显示“更正自”“已更正为”，写交易号，不做链接。
- 状态正常的存款、取款、兑换、调账，银行管理员在详情按钮行里多一个“编辑”（`dc-btn-ghost dc-btn-sm`，图标 `settings`），排在“冲正”前面。冲正生成的流水、利息、工资、定期、理财、贷款都没有“编辑”。

## 补录

后台“流水”页的页面主操作“补录”（图标 `plus`，`dc-btn-primary`，与页头其他按钮同为 `dc-btn-sm`），只给银行管理员；电脑上在页头右边，手机上放进 `ActionBar`。点开是一个单独的页面“补录流水”（返回到流水页），从上到下：

1. **学生**：`SearchField`“输入姓名、拼音、班级或学号”，选中后换成 `PersonCard`（姓名、班级、学号、活期余额）和“换一位”。注销的账户搜不到；冻结、毕业的可以补录，`PersonCard` 上照常显示状态标签。
2. **类型**：`Segmented`：存款 / 取款 / 兑换 / 调账。
3. **原始发生时间**：`DatePicker`（日期）和 `TimePicker`（时刻）上下排列（日期写全“2026年11月12日 星期四”，并排会折行），默认现在；下面 `dc-field-hint`“可补录 9月1日 08:30 开户以后的业务”，时间取这位学生的开户时间，还没选学生时写“选好学生后，可补录开户以后的业务”。早于开户和晚于现在的日期在月历里不可选。
4. **内容**，按类型：
   - 存款：`QtyStepper`（`dc-denoms dc-kind-save`）录收到的面额张数，下面合计“合计 25 HTB”。
   - 取款：`Field`“取款金额”（HTB，整数）；下面 `dc-btn-ghost dc-btn-sm`“录入面额”，展开后是 `QtyStepper`（`dc-kind-withdraw`），合计要等于金额。不录时按柜台的配钞。
   - 兑换：商品 `QtyStepper is-product`（与柜台“兑换”相同）、付款方式 `Segmented`（账户 / 现金）；现金时再录收到的面额，下面写“应付 18 HTB，收到 20 HTB，找零 2 HTB”。
   - 调账：`Segmented`（增加 / 减少）和 `Field`“调账金额”（HTB，整数，1～100000）。
5. **原因**：多行 `Field`，必填，最多 100 字，提示“写清为什么补录，例如：系统故障，当天未记”。

`ActionBar` 主按钮“补录”，合计写“补录存款 25 HTB”（调账“调账 −20 HTB”）；学生、类型、内容或原因没填好时按钮禁用。

### 确认补录

`Sheet`，标题“补录张小明的存款 25 HTB？”（调账写“给张小明调账 −20 HTB？”）：

- `SummaryList`：学生“张小明 · 20260001”、类型“存款”、金额“25 HTB”、原始时间“11月12日 14:20”、活期余额“415 → 440 HTB”（现在的余额加上这一笔）。
- 下面一行 `caption`：“记在 11月12日 14:20，之后已经算过的活期利息随之更正，差额在下次结息时入账。不计入任何柜员的上班现金。”
- 按钮“取消”“确认补录”。服务器拒绝时错误写在弹层里，弹层不关（见下面“错误”）。
- 成功后回到流水页，新的一笔加 `is-new`，`Toast`“已补录，利息更正 +0.15 HTB”（`interest[].centi` 的合计，两位小数，带正负号）；没有更正时“已补录”。

## 编辑

详情里点“编辑”，进入“编辑流水”页面，和补录是同一张表单：

- 页头写“编辑 HT2611120000123”，下面 `caption`“原流水冲正，按改好的内容记一笔新流水，时间不变。”
- 预填原流水的学生、类型和内容；学生可以换（“换一位”），类型可以改。
- 原始时间锁定为原流水的时间：`DatePicker`、`TimePicker` 加 `disabled`，换成 `lock` 图标，提示“编辑时间固定为原流水的时间”。
- 原因不用自由填写，选冲正的四项（`Radio`，与冲正相同）。
- `ActionBar` 主按钮“编辑”；内容和原流水完全相同时按钮禁用。

### 确认编辑

`Sheet`，标题“编辑 HT2611120000123？”：

- 一张三列 `DataTable`：项目、原来、改为；行是学生、类型、金额，改了的那一格加粗。下面 `SummaryList` 一行活期余额，改了学生时两位学生各一行：“张小明 415 → 405 HTB”“李小红 120 → 130 HTB”。
- 下面一行 `caption`：“原流水冲正，按改好的内容记一笔新流水，两笔都记在 11月12日 14:20，利息随之更正。”
- 按钮“取消”“确认编辑”。
- 成功后回到流水页，展开新的一笔，`Toast`“已编辑，利息更正 −0.08 HTB”（没有更正时“已编辑”）。

## 错误

服务器拒绝时写在弹层里（`Notice`，`danger`），弹层不关：

| 错误 | 文案 |
| --- | --- |
| `OCCURRED_OUT_OF_RANGE` | 标题“时间不在补录范围内”，说明“只能补录 9月1日 08:30 开户以后到现在之间发生的业务。”（时间取 `from`），同时更新表单的提示 |
| `INSUFFICIENT_BALANCE`，带 `at` | “补录后，11月12日 14:20 起活期会不够，差 30 HTB。” |
| `REVERSAL_NOT_ALLOWED`（编辑时） | “这笔流水已经冲正或编辑过，不能再编辑。” |

## 筛选、报表与日志

- 后台流水的类型筛选加“调账”，排在“兑换”后面；报表的余额变动加一行“调账”，排在“利息”后面，金额取 `balance.changes.adjust`（与其他行一起加到期末余额）；笔数和净额 `adjust.count`、`adjust.amount` 写在业务的说明句和打印的营业概况里。
- 日志页“流水”分类加 `txn.manual`“补录流水”、`txn.correct`“编辑流水”。

使用者提供：学生、类型、按类型的内容、原始时间、原因（编辑时还有原流水）；补录的范围起点；服务器返回的利息更正合计。
