## 第一部分：功能需求概要

### 系统架构总览

**明德海豚银行管理系统**，分后台、前台、数据库三层，前台有电脑终端和手机终端两个入口。

- **电脑终端：银行管理系统（功能实现）**
  1. 个人业务：办理学生的查、存、取、贷、转、兑换等业务
  2. 对公业务：在管理系统里实现学部与级部、班级间业务往来（包括海豚币发放、奖励、回收等）
  3. 教师对学生海豚币的管理，包括发放（含工资发放）、奖励、扣除等操作
  4. 银行工作人员报表功能（营业报表、用户报表、财务报表等）
- **手机终端（智慧校园）**
  - **家长端**
    - 家长可查询孩子的帐务信息
    - 可预约办理业务时间
    - 帐务信息有变化即时通知家长
  - **教师端**
    1. 对公业务：在管理系统里实现学生处与班级间业务往来（包括海豚币发放、奖励、回收等）
    2. 班主任/科任老师对各班学生海豚币的管理，包括发放、奖励、扣除等操作
    3. 可查询所有学生的帐务信息，以及查看各种报表
    4. 社团老师管理社团学生，包括发工资

### 需求说明

#### 一、后台需要功能

1. 每个学生需要有一个银行帐号，对应有海豚币数据。
2. 数据导入，我们现在的帐本是一张 Excel 表，里面用公式的计算来实现存入、取出、利息计算。
3. 需要实现利息计算。
4. 线上积分转为海豚币，如按 10:1 比例（待定）。
5. 兑换商品库存功能，如上架下架。

## 第二部分：校园银行线上平台开发需求说明书

### 一、用户角色与权限

| 角色 | 谁 | 权限范围 |
| --- | --- | --- |
| 学生 | 全体社员及开户学生 | 查询本人余额、明细、贷款；修改本人密码。不能发起任何账务操作。 |
| 柜员 | 出纳、支行负责人（当班） | 办理存款、取款、兑换/购买、贷款申请录入；发起冲正申请。不能改余额、不能审批、不能删流水。 |
| 会计 | 老成员（复核岗） | 查看全部流水、日终轧账、导出报表、登记实物清点结果。不能办理业务。 |
| 库管 | 老成员 | 文创商品上架/下架、入库登记、库存盘点。 |
| 行长 | 学生负责人 | 审批 ≤ 限额的贷款；查看本班数据。 |
| 指导老师 | 管理员 | 货币发行与回收、审批超额贷款、教师工资发放、用户与权限管理、查看全部报表、参数设置（限额/面额/学期）。 |
| 系统管理员 | 信息技术老师 | 账号维护、数据备份与恢复、日志审计。不得修改业务数据。 |

**权限设计要点：** 办理与审批必须分离；柜员可“发起”但不可“批准”；任何删除操作改为“作废/冲正”，保留原记录。

### 二、核心业务流程

#### 2.1 开户与身份识别

1. 老师批量导入学生名册（学号、姓名、班级），系统自动开户，初始余额 0。
2. 学生身份识别方式（三选一，建议 ①）：
   - ① 二维码胸卡（打印发放，柜台扫码枪/平板摄像头识别）；
   - ② 学号 + 密码；
   - ③ 刷卡（如学校有校园卡）。
3. 四年级学生不建议依赖记忆力输入学号，强烈建议采用扫码方式，避免输错。

#### 2.2 存款

1. 柜员点击“存款” → 识别学生身份 → 系统显示姓名、班级、当前余额。
2. 柜员按面额输入张数（1/2/5/10 元），系统自动算总额并高亮显示。
3. 确认提交 → 生成流水（交易号、时间、柜员、类型、金额、面额明细）→ 余额实时增加。
4. 可选择打印小票凭条（建议打印，作为纸质兜底）。

#### 2.3 取款

1. 识别身份 → 系统校验余额：余额不足时直接禁止提交（硬约束，不允许透支）。
2. 输入金额 → 系统提示配钞方案（10 元 × 张、5 元 × 张……），方便柜员配钱。
3. 提交 → 余额扣减 → 打印凭条，请学生签字（小票留存，班次结束后装订）。

#### 2.4 购买 / 兑换文创

1. 识别身份 → 进入“商城”，显示商品名、图片、价格、实时库存（库存为 0 时置灰不可选）。
2. 加入购物车 → 结算时系统显示：应付金额、当前余额、找零方案。
3. 余额不足则禁止结算；提交后：余额扣减 + 库存减 1 + 生成流水（三件事同一个事务，要么全成功要么全失败）。
4. 打印凭条（品名、价格、找零），凭条即为取货凭证。

#### 2.5 贷款申请与还款

1. 柜员录入申请（金额、用途、还款计划），系统自动校验：该生是否有未结清贷款（有则拦截）。
2. 按金额路由审批：≤ 限额（默认 50）由行长审批；> 限额由指导老师审批。
3. 批准后放款（余额增加、贷款本金增加）；还款时逐期登记，逾期自动标红并暂停该生新贷款申请。

#### 2.6 日终轧账（每班次）

1. 系统按当班柜员自动汇总：收款合计、付款合计、应存现金。
2. 会计录入储蓄盒实物清点结果（各面额张数），系统自动比对。
3. 平账 → 一键“轧账完成”，该班次流水锁定不可再修改；不平 → 显示差额并列出当班流水供逐笔核查。
4. 老师端次日可见“昨日轧账状态”，未轧账的班次标红提醒。

### 四、关键业务规则（需系统硬编码）

| 规则 | 说明 |
| --- | --- |
| 余额不可直接修改 | 余额 = 期初 + 流水汇总；任何调整必须通过“发行/冲正/补录”生成流水实现。 |
| 禁止透支 | 取款、消费时余额不足直接拦截，不提供“临时透支”。 |
| 最小金额单位 | 1 元（如后续发行 0.5 元币种，需改为 0.5）。所有输入做整数校验。 |
| 单笔/单日限额 | 可配置参数，建议单笔取款 ≤ 200、单日累计 ≤ 500（老师可调）。 |
| 交易号唯一且幂等 | 交易号全局唯一；同一交易号重复提交只生效一次，防止网络重试造成重复记账。 |
| 库存不能为负 | 库存为 0 时商品不可选；并发购买时后到者收到“已售罄”。 |
| 流水不可删除 | 错误通过“冲正”生成反向流水，原流水保留并显示作废标记。 |
| 轧账后锁定 | 班次轧账完成后，该班次流水不可再修改，需老师权限解锁。 |
| 学期结转 | 学期末一键结转：余额清零或结转至下学期，历史数据归档不可改。 |

### 五、数据模型（主要实体）

| 数据表 | 主要字段 |
| --- | --- |
| 学生 `Student` | 学号 (PK)、姓名、班级、年级、入学届、开户日期、状态（正常/冻结/毕业） |

| 班次 `Shift` | 日期、午别（中午/下午）、窗口、当班人员、轧账状态、实物清点金额、系统金额、差额、复核人 |

**要求：** 交易流水表必须支持“按班次、按学生、按日期、按类型”四类组合查询；所有金额字段用整数（分或元）存储，禁止浮点。

### 六、界面与交互要求

#### 6.1 页面清单

- **柜台收银台**（平板横屏，主界面）：六个大按钮——存款/取款/购买/贷款/还款/查询。字号大、按钮大、一步一屏。
- **学生查询页**（自助查询机或平板）：扫码或输入学号 → 显示余额、最近 10 笔、贷款状态。
- **后台管理页**（电脑浏览器）：商品管理、库存盘点、发行登记、贷款审批、报表、用户权限、日志。
- **经营看板页**：6 个核心指标 + 按周业务柱状图 + 轧账状态提醒。

#### 6.2 易用性要求（面向小学生）

- 柜台主界面单屏可见核心操作，点击层级不超过 2 层；数字输入使用大号数字键盘。
- 关键动作（提交取款、结算）需二次确认，并大声朗读金额（可选语音提示）。
- 错误提示用儿童能懂的话：“余额不够啦，你还有 8 元”，不用“余额不足，错误码 E002”。
- 成功页显示大字结果：“存入 15 元，你的余额是 43 元”。
- 界面文字与《柜台业务 SOP 卡片》保持一致，学生培训成本最低。

### 七、非功能需求

| 项目 | 要求 |
| --- | --- |
| 性能 | 并发极低（峰值约 2 笔/分钟），但单笔响应须 < 1 秒；查询页 < 2 秒。 |
| 可用性 | 仅需营业时段（中午 15 分钟、周一周四下午）稳定可用；允许非营业时段维护。 |
| 断网兜底 | 网络中断时，柜台可切换“离线登记模式”暂存本机，恢复后一键批量补传；同时保留纸质单据作为最终兜底。 |
| 数据准确 | 账务操作全部走数据库事务；日终轧账差异必须能逐笔追溯到人和时间。 |
| 安全与隐私 | 不采集学生身份证号、家庭住址、家长信息；数据传输 HTTPS；密码加密存储；导出报表默认脱敏（可配置）。 |
| 备份 | 每日自动全量备份，保留 30 天；每学期归档一次；每学期演练一次恢复。 |
| 兼容性 | 柜台端支持平板（iPad/安卓）与电脑浏览器；后台支持 Chrome/Edge。 |
| 可维护性 | 关键参数（面额、限额、学期、安全库存、审批额度）后台可配置，改参数不需要改代码。 |
