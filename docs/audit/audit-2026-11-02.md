## 一、结论

**总体 8.2/10。** 新增的报表、考勤工资、上下班、批量管理、注销、查询筛选与 PDF/Excel 导出不是“演示壳子”：数据库函数、权限、余额自检、pgTAP、生产镜像 E2E 都覆盖到了，账务不变量仍然成立，升级测试通过。

但当前 `main` **不能以绿灯状态发布**：

1. **CI 会在 smoke 测试处失败**。产品把密码规则改成“至少 8 位、可以全是数字”（`docs/development/PHASE-1.md:447`），`docker/smoke-test.sh:92-97` 还在要求 `abcdefgh` 必须被拒绝。`.github/workflows/ci.yml:67` 会执行该测试，因此构建镜像后的流水线必红。实测失败点：`FAIL: password abcdefgh accepted (200)`；后续的上传、加密备份、恢复、重启检查都没有执行到。
2. **“在此设备保存登录”关闭后，登录状态仍会跨浏览器重启保留。** Supabase 客户端使用默认持久化（`client/src/lib/supabase.ts:9-11`），`rememberSession` 对 `saved:false` 的账号也写入 access/refresh token（`client/src/lib/accounts.ts:33-45`），而 `leave()` 只在切换账号时清理（`:68-70`），关闭开关本身只改标记（`client/src/components/Accounts.tsx:137-138`）。在公用设备上，用户以为已退出，重新打开页面仍会直接进入该账号。
3. **8 位纯数字密码 + 只按账号锁定**，是文档明确选择，但强度明显偏低；同一 IP 可以不断换账号尝试，没有全局登录失败限流。作为校园系统可以接受，但应作为显式风险记录，并在入学教育/首次改密里提示。

其余为中等风险：上下班加载态绕过、跨午夜下班总结、备份加密是可选配置且没有异地、报表/PDF 在 10 万流水下的性能、教师与运维员的账号治理不对称等。详见第四节。

## 三、本轮新增能力复核

### 3.1 报表与导出

`bank_report`（`20261103000000_queries_reports.sql`）覆盖营业、账户、财务、商品四类；期初 + 变动 = 期末，现金收支、柜员/班级/学生分布、商品成本与库存、发行登记都在内；`reportPages` 生成 A4 PDF，`ledgerSheet` 生成 Excel。E2E 校验了今日数字、图表、余额核对、PDF 下载、打印对话框。

优点：

- 报表口径写清楚了：已冲正业务、现金兑换、工资、注销清零分别处理；期初/期末与 `balance_after` 一致。
- 前端有“上期对比”、时间段、学生/班级/学部范围；筛选条件与报表参数一致。

注意：

- 报表是多次全期间扫描（约 366 天上限）。10 万流水、整年、全学部时没有性能测试；PDF/Excel 会把结果一次性读入内存。
- 账户状态只统计在读/冻结/毕业，不含已注销；文档也只承诺这三类，不算错误，但“学生总数”和三项之和可能不相等，导出时容易被误读。

### 3.2 考勤、工资、上下班

- `bind_salary_account` 用学生账户密码绑定工资账户，错误计入学生账号锁定；`set_attendance` 必须已绑定；`pay_salaries` 按周、按中午/下午班工资发放，跳过停用/未绑定/非在读，写入 `salary` 流水并记录每班工资。
- `start_duty`/`end_duty` 记录上下班；`require_duty` 触发器禁止未上班的柜员办理存款/取款/兑换/冲正（离线存款例外）；`end_duty` 会核对打印总结的笔数。
- E2E 覆盖：绑定、参与考勤、上班/下班、审查、补签、发放、柜员看到工资、学生明细看到工资。

注意：

- 上下班页面在 `duty.data === undefined`（首次加载/查询失败）时显示的是柜台搜索，而不是“请先上班”（`client/src/app/counter/index.tsx:85`）。在线办理会被服务器以 `OFF_DUTY` 拒绝，但页面会先让柜员进入学生页；离线存款又是允许的，所以这个空窗对离线存款是真实可用的。
- `dutyCount`/`dutySummary` 用柜员自己的 RLS 读 `txns`，而柜员只能看“当天”的流水；跨午夜（例如 23:30 上班、00:10 下班）时客户端总结会少算前一天的笔数，`end_duty` 用 security definer 看到全部笔数，于是报 `SUMMARY_STALE`，柜员无法正常下班。没有跨午夜 E2E。
- `start_duty` 会在开始和结束时各签一次当前班次；跨 13:30 的上班会同时签上午班和下午班。这可能是预期（确实跨了两个班），但文档没有明确。

### 3.3 注销、批量、设备账号

- `close_accounts` 有二次确认、余额清零 `closing` 流水、状态 `closed`、禁用登录、结束会话、解绑工资账户；`set_student_status` 只允许在读/冻结/毕业。
- 学生与人员列表都支持批量选择、批量停用/启用/重置/注销；密码单/开户通知单走 PDF。
- 设备账号支持保存登录、切换账号、添加账号、退出全部；保存开关需要当前密码。

注意：

- “保存登录”只影响切换是否需要密码，**没有阻止 Supabase 的会话持久化**，见 P0-2。
- 教师可以重置/停用/注销运维员，运维员不能反向操作教师（`20261105000100_accounts.sql` 只 `guard_teacher`；`create_staff`/`set_role` 也只挡教师）。`PHASE-1.md` 的权限矩阵确实同时给了教师和运维员“管理工作账号”，所以这是**治理风险/设计选择**，不是实现偏离文档；但业务管理员可以把唯一运维员锁在门外，建议至少加“不能停用最后一个运维员”或双人确认。

### 3.4 柜台查询、筛选与流水

- 柜台新增“查询”页，调用 `student_txns` 翻页；可按交易号/商品、日期、时段、类型筛选，办理后自动刷新。
- 学生明细新增类型标签（全部/存款/取款/兑换/工资），现金兑换在“全部/兑换”和月度兑换中可见，余额不变；管理端流水支持学生/柜员/交易号搜索、时段、类型、Excel/PDF。
- E2E 覆盖柜台查询、学生明细搜索、报表流水导出。

注意：

- 学生月度合计查询没有分页（`client/src/app/student/txns.tsx:66-74`）。Supabase/PostgREST 默认最多返回 1000 行；单个学生一个月超过 1000 笔时合计会少算。当前业务量下概率低，但应改成聚合 RPC 或 `readAll`。
- 商品名搜索先查 `txn_items` 并 `.limit(500)`（`:54`），超过 500 条匹配会漏；可改为数据库函数内联查询。
- 管理端冲正按钮的 `canReverse` 只排除 `reversal`/`salary`（`client/src/app/admin/txns.tsx:230`），`closing` 会显示“冲正”，服务端 `reverse_txn` 会拒绝。属于低优先级 UI 误导。

## 四、问题清单

严重度：**P0** 阻断发布/高危；**P1** 上线前应修；**P2** 首个迭代修；**P3** 记录即可。

### P0

**P0-1 CI smoke 测试过期，发布门禁必红**

- 证据：`docker/smoke-test.sh:92-97` 要求 `abcdefgh`、`12345678`、`abc1234` 都返回 422 `weak_password`；`docker/supervisord.conf:45` 只有 `GOTRUE_PASSWORD_MIN_LENGTH="8"`；`docs/development/PHASE-1.md:447` 明确“可以全是数字”；`client/src/app/change-password.tsx` 也已允许纯数字。
- 实测：smoke 在 `FAIL: password abcdefgh accepted (200)` 停止；`abcdefgh` 是 8 位，按当前策略本来就应接受。
- 影响：`.github/workflows/ci.yml:67` 的镜像 job 失败，主分支无法发布；而上传、加密备份、恢复、重启这几项 smoke 检查也未得到验证。
- 修复：二选一——把 smoke 改成“8 位接受、<8 拒绝”，并同步注释/文档；或恢复字母+数字策略。两者必须与 `PHASE-1.md:447`、`change-password`、seed/e2e 一致。修复后重跑 smoke，确认备份/恢复/重启段落。

**P0-2 “不保存登录”仍持久化会话，重新打开浏览器会自动登录**

- 证据：`client/src/lib/supabase.ts:9-11` 未配置 `auth.storage`/`persistSession:false`；`client/src/lib/accounts.ts:33-45` 对 `saved:false` 也写入 `{access_token, refresh_token}`；`:68-70` 的 `leave()` 只在切换账号时清未保存会话；`client/src/components/Accounts.tsx:137-138` 关闭开关只 `setSaved(id,false)`；`client/src/lib/session.tsx:21-27` 启动时直接采用 `getSession()` 的结果。
- 结果：用户不勾选“在此设备保存登录”登录后，Supabase 默认存储和 `dolphin.accounts` 都保留会话；关闭标签/浏览器再打开页面会直接进入该账号。界面却把该账号标成“需要输入密码”，与事实不符。
- 影响：公用电脑/教室平板上，下一位使用者可以直接看到上一个账号的余额、流水、工资；这是隐私问题，不是普通体验问题。
- 修复建议：给 Supabase 客户端用自定义 `storage`：只有 `saved` 账号才写 localStorage，未保存账号写 sessionStorage 或只在内存；关闭开关时同时删除该账号的持久化会话；增加“关闭后重新打开必须重新登录”的 E2E。

### P1

**P1-1 密码强度与登录限流**

- 现状：初始密码、重置密码、用户自设密码都可为 8 位纯数字；GoTrue 只配了最小长度 8；锁定是“同一账号 15 分钟内 5 次错，锁 15 分钟”（`20261102000000_login_lockout.sql`）。
- 风险：8 位数字空间 10^8，按账号锁定后单账号可接受；但攻击者可轮换学号/工作账号，没有 IP/设备级全局限流；`bind_salary_account` 也会消耗学生账号的失败计数（`20261104000100_attendance.sql:191-216`），可被用来锁学生。
- 建议：至少 10 位，或恢复“字母+数字”；登录失败加 IP/设备级速率限制；在文档里把“可以全是数字”标为风险接受项，并同步 smoke。若坚持纯数字，应把初始密码改为 10–12 位。

**P1-2 上下班加载/失败态绕过**

- `client/src/app/counter/index.tsx:85` 只在 `duty.data === null` 时显示“上班”；`useDuty` 首次没有缓存时 `data` 是 `undefined`（`client/src/lib/duty.ts:13-31`），页面会先显示搜索框。查询失败同样如此。
- 在线业务会被 `require_duty` 拦住，但柜员已经进入学生页/业务面板，体验与权限提示都不对；离线存款又允许在未上班时登记，因此不是纯视觉问题。
- 修复：用 `duty.isPending`/`isError` 或 `duty.data !== undefined` 做门；加载显示骨架，失败显示重试，不要显示柜台。

**P1-3 跨午夜下班总结**

- `dutyCount`/`dutySummary`（`client/src/lib/duty.ts:45-51` 及后续查询）按 `created_at >= duty.started_at` 读 `txns`；柜员 RLS 只暴露“当天”流水，跨午夜时客户端少算前一天，服务端 `end_duty` 用 security definer 全算，笔数不一致时报 `SUMMARY_STALE`。
- 也没有跨午夜 E2E。建议：`dutyCount`/`dutySummary` 改走 security definer RPC（校验调用者是值班柜员），或明确禁止跨午夜值班。

**P1-4 备份加密是可选配置，且缺少异地/恢复演练**

- `BACKUP_RECIPIENT` 未设置时备份仍是明文 tar.gz；README/PHASE-1 说生产“应设置”，但默认安装不会强制。备份文件含 auth 哈希、会话、学生数据。
- 备份 600、audit 已修；`restore` 的挂载点数据丢失问题已修；但 smoke 未跑到加密备份/恢复段，升级测试也只验证升级前备份，不验证恢复。
- 建议：生产安装向导/文档把 recipient 设为必填；增加异地副本（对象存储/另一块盘）与定期恢复演练；CI 增加“无 recipient 时拒绝生产启动”或至少告警。

**P1-5 报表/PDF 在 10 万流水下的性能与内存**

- `bank_report` 在整年、全学部、10 万流水时做多次 CTE 扫描；`ledgerPages` 把筛选后的全部行画进 PDF；`ledgerSheet` 全部写进 Excel；`reportPages` 也一次读完。没有对应 perf 测试，现有 perf 脚本仍只测学生首页/存取/后台流水。
- 建议：给 `bank_report` 加 10 万行基准；PDF/Excel 设上限或流式分页；对“全部学生 + 一年”给出耗时提示。

**P1-6 教师/运维员治理不对称（文档已授权，但仍是风险）**

- 教师可以创建/重置/停用/注销运维员；运维员不能对教师做同样操作。`PHASE-1.md` 权限矩阵同时给两者“管理工作账号”，所以不算偏离文档；但教师可以把唯一运维员锁死，且没有“最后一个运维员”保护。
- 建议：明确这是业务选择；若保留，增加“不能停用/注销最后一个运维员”或双人确认；在运维手册里写明恢复路径（`dolphin create-admin`/数据库直连）。

**P1-7 退出登录只结束本地会话**

- `signOutCurrent`/`signOutAll` 都用 `scope:'local'`（`client/src/lib/accounts.ts:99-104` 及后续），refresh token 服务端未撤销；access token 最长 1 小时仍有效。共享设备上“退出”后，若 token 已被复制仍可用。
- 建议：退出时调用服务端撤销（至少当前会话），或把 access token 有效期缩短；对高权限账号（教师/运维）提供“退出所有设备”。

**P1-8 学生月度合计最多 1000 行**

- 见 3.4。改为数据库聚合或分页读取；加一个“超过 1000 行”的测试。

## 五、数据库与账务

**仍然成立的部分**

- 余额只由 `txns.balance_delta` 推导；存款/取款/账户兑换/现金兑换/冲正/工资/注销清零都在同一套账户锁下更新；`accounts.balance >= 0`。
- `deposit`/`withdraw`/`purchase`/`reverse_txn` 先锁账户、再校验、再插入；商品按 id 排序锁；买最后一件的并发只有一人成功（08_concurrency）。
- 幂等键 `p_id`；冲正只能对 normal 的存款/取款/兑换（教师可冲期初），柜员只能冲本人当天；`salary`/`closing` 不可冲。
- `check_balances` 本轮扩展到 `balance_after` 链、`total_in/out/spent`、购买明细与金额；07_check_balances 会人为篡改并断言具体行，300 个 pgTAP 全过。
- RLS 仍是 SELECT-only；写入口只有 security definer RPC；`create_login`/`create_admin`/`reset_admin` 不暴露给 API；存储策略只允许库管/教师写。

**仍建议关注**

- `check_balances` 不检查 `txn_no` 唯一性之外的编号连续性，也不检查 `txn_items` 对非 purchase 的引用；不影响余额，但可发现数据损坏。
- `bank_report` 的 `students.total` 含 closed，而 normal/frozen/graduated 不含；要么增加 closed，要么把 total 改名，避免导出误读。
- `close_accounts` 的 `closing` 流水不计入 `total_out`，`salary` 不计入 `total_in`，这是现有口径；`check_balances` 也按此口径，所以一致，但报表读者需要文档解释。
- `duty` 的 `txns` 计数是“按 operator_id + created_at”，包含离线补传和冲正；同一柜员在值班期间替别人冲正也会算进总结，符合“本人办理”的定义。
