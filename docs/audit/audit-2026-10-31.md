### 0.3 新发现的问题

#### R-1 开户通知单重发可能永久卡在 loading（中）

- `client/src/app/admin/students/index.tsx:38-53`：`reissue_passwords` 返回人数只要与 `nos.length` 不相等（例如某个学生刚自己改了密码），`setReissue(null)` 不会执行，按钮一直转圈；`downloadNotices(accounts)` 抛错也没有 catch，同样卡死。

- **建议**：`try/finally` 收尾、空数组保护、busy 时禁用按钮；部分成功时明确提示“前 N 人已重发”。

## 三、主要优点

1. **权限模型清晰**：业务表只授予 `authenticated` 的 `SELECT`，写操作全部走 security definer RPC；所有 RPC 都 `set search_path = ''`，RLS 策略按角色/本人/当日柜员细分。
2. **账务完整性**：余额只由 `txns.balance_delta` 推导；`append_only` 触发器禁止改账；冲正只能反向、不能删除；开户唯一；账户/商品按固定顺序 `FOR UPDATE` 锁；库存非负。
3. **幂等与离线**：存款按 `p_id` 幂等；柜台离线存款进 IndexedDB，联网后按时间顺序上传；PWA 可离线加载。
4. **运维成熟度**：单镜像、supervisord、自签名/挂载证书、自动迁移、每日备份、恢复前先备份、`dolphin check` 对账、smoke/perf/e2e 脚本齐全。
5. **前端工程化**：Expo Router、React Query、设计系统 token 生成、日期选择器、拼音搜索、打印通知单、错误码中文化都做得完整。
6. **文档质量高**：`PHASE-1.md` 对决策、RLS、RPC、错误码、验收标准写得非常具体，代码与文档总体一致。

## 四、问题清单（修复前基线；当前状态见第零章）

> 以下条目保留初版原文用于追踪；逐条当前状态见 **0.2**，不要直接按本章判断某项是否仍存在。

### P0：上线前必须处理

#### H-1 统一初始口令 + 密码登录无失败限速/锁定（高）

- **证据**：
  - `supabase/migrations/20261028000300_default_password.sql:5` 固定初始密码 `a12345678`；
  - `client/src/components/Notices.tsx` 批量打印该密码；
  - `docker/supervisord.conf:43-52` 只配置了 8 位最小长度、禁用注册、refresh/verify 限速，**未见针对密码登录失败的限速或账号锁定**。
- **影响**：校内学号可枚举；知道初始口令即可在用户首次登录前冒用账号（尤其刚导入、尚未改密的学生）。GoTrue 访问日志也不进业务审计，攻击难以发现。
- **建议**：
  - 导入/新建账号改为**每人随机初始密码**，打印或单独发放，不再共享 `a12345678`；
  - 在 Caddy 或 GoTrue 前增加 `/auth/v1/token` 的 IP/账号失败限速与告警；
  - 连续失败 N 次锁定一段时间（GoTrue 无内置锁定，可用反向代理或定时任务实现）。

#### H-2 公共图片桶 + `/storage` 无 CSP + 任意 MIME → 同源存储型 XSS（高）

- **证据**：
  - `supabase/migrations/20261027000000_login_helpers.sql:43` 创建 `public=true` 的 `product-images` 桶；
  - `docker/supervisord.conf:104` 只限制 5 MB，未限制 MIME；
  - `docker/Caddyfile:24-26` 的 `/storage/v1/*` 反代**没有** CSP；CSP 只加在 SPA 的 `handle` 块（`docker/Caddyfile:33`）。
- **影响**：库管/银行管理员账号可上传 `.html`/`.svg` 等文件；若管理员直接打开该同源链接，脚本可读取 `localStorage` 中的 access/refresh token，进而接管管理员会话。属于内部人员提权路径。
- **建议**：
  - 桶保持私有，改用签名 URL；或至少设置 `allowed_mime_types = {image/jpeg,image/png,image/webp}`；
  - 给 `/storage/v1/*` 加 `Content-Security-Policy: default-src 'none'; sandbox` 和 `Content-Disposition: attachment`（图片除外）；
  - 全站补 `X-Frame-Options: DENY` / `frame-ancestors 'none'`。

### P1：试点后一个月内处理

#### M-1 银行管理员可创建/重置/停用 sysadmin（中高，职责分离）

- **证据**：
  - `supabase/migrations/20261031000000_one_bank_admin.sql:7` 的 `create_staff` 只在第 24 行拦截 `p_role='teacher'`，**不拦截 `sysadmin`**；
  - `client/src/app/admin/staff/new.tsx:15` 的角色列表只排除了 teacher，因此 UI 可直接创建 sysadmin；
  - `20261028000300_default_password.sql:60` 的 `reset_password` 和 `20261028000200_admin.sql:186` 的 `set_user_disabled` 也只通过 `guard_teacher` 保护 teacher，不保护 sysadmin。
- **影响**：银行管理员可创建、改密、停用运维账号，角色隔离被打破；也可借此把运维账号锁死。
- **建议**：明确角色管理矩阵——sysadmin 账号只能由 sysadmin 管理；teacher 只能管理 teller/accountant/storekeeper；在 RPC 和 UI 双重限制。

#### M-2 现金消费在学生端和教师“最近流水”中不可见（中）

- **证据**：
  - `client/src/app/student/index.tsx:22-23`、`client/src/app/student/txns.tsx:40-42`、`client/src/app/admin/students/[no].tsx:26-27` 都加了 `.neq('balance_delta', 0)`；
  - 现金购买 `balance_delta = 0`（`supabase/migrations/20261028000100_accounting.sql:228-236`）。
- **影响**：
  - 学生首页最近 10 条看不到现金购买；
  - “全部”页签实际不是全部；
  - 月份支出合计也排除现金消费；
  - 教师学生详情的最近流水缺失。
- **建议**：`全部`/最近流水改用 `type/status` 条件，保留现金购买并显示“现金支付、余额不变”；或增加“现金消费”页签。

#### M-3 `check_balances` 覆盖不足（中）

- **证据**：`supabase/migrations/20261028000100_accounting.sql:312-327` 只校验 `accounts.balance` 对 `sum(txns.balance_delta)`、`products.stock` 对 `sum(stock_movements.qty_delta)`。
- **未校验**：`balance_after` 链、`total_in/total_out/total_spent`、`txn_items` 合计与 `purchase.amount`、`txn_no` 唯一性/格式、`status` 与冲正关系。
- **影响**：某些类型的静默错账不会被每日巡检发现。
- **建议**：扩展为多项检查，返回统一失败码；`dolphin check` 失败时接入告警。

#### M-4 备份未加密、权限过宽、无异地、无审计（中）

- **证据**：`docker/bin/dolphin:9-19` 的 `backup()` 用 `tar -czf` 生成默认权限文件（通常 644），内容包含 `auth.users` 的 bcrypt hash、session/refresh token、全部学生数据；无加密、无异地副本；备份/恢复动作不写 `audit_log`。
- **影响**：宿主机或备份卷一旦泄露，等价于泄露全部账号与会话材料。
- **建议**：`umask 077` / `chmod 600`；用 `age` / `gpg` 加密；至少复制一份到异地；`backup` / `restore` 写审计并告警。

#### M-5 应用服务以 root 运行（中）

- **证据**：`docker/supervisord.conf:3` `user=root`；`postgres` 通过 `docker-entrypoint.sh` 降权，但 `auth/rest/storage/caddy/migrate/cert-watch/backup-schedule` 均无 `user=`，storage 的 Node 进程（约 :84）也以 root 运行。
- **影响**：任一服务 RCE 即容器内 root，扩大逃逸面。
- **建议**：为各服务建立低权限用户；Caddy 用 `cap_net_bind_service`；只读 rootfs + 可写挂载最小化。

#### M-6 登录/失败登录没有业务审计（中）

- **证据**：`audit_log` 的触发器只覆盖 profiles / user_roles / students / products / currency_issues / settings（`core_schema.sql` 审计段），GoTrue 的登录事件只进容器 stdout。
- **影响**：初始口令撞库、异常登录、账号共享无法在后台审计页发现。
- **建议**：收集 GoTrue 日志到集中存储；或在反向代理层记录 `/auth/v1/token` 的成败（脱敏）；后台增加登录审计视图。

#### M-7 离线队列的错误条目无法清理（中）

- **证据**：`client/src/lib/offline-queue.ts:21-32` 上传时遇到非 NETWORK 错误会标记 `error` 并继续，但条目**永不删除**，每次上传都会重试；UI 没有“删除/标记已处理”入口。
- **影响**：学生冻结/学号变更等永久错误会一直卡在待上传列表，柜员无法收尾。
- **建议**：错误条目提供“查看原因/删除/转人工”操作；成功或人工处理后移除；上传加互斥锁避免多标签页重复。

#### M-8 幂等并发竞态（中低）

- **证据**：`deposit` / `purchase` / `reverse_txn` 都是先 `select ... where id = p_id`，再 insert；两个并发同 id 请求会有一个撞 `txns` 主键，返回 23505 而不是幂等结果。
- **影响**：弱网重试/双击时偶发“操作失败但实际已成功”，柜员可能重复操作。
- **建议**：`insert ... on conflict (id) do nothing` 后回查；或对 `p_id` 加 advisory lock；补并发测试。

#### M-9 柜台花名册缓存 10 分钟（中低）

- **证据**：`client/src/lib/counter.ts:63-66` `useRoster` `staleTime: 10*60_000`，且只在 `counter/_layout` 挂载一次；新导入学生在柜台最多 10 分钟搜不到。
- **建议**：`refetchOnWindowFocus` / 定时刷新 / “刷新名册”按钮；导入后在本机主动失效。

#### M-10 关键操作无二次确认（中低，需求冲突）

- **证据**：`client/src/components/Business.tsx:17-19` 注释明确“主按钮一次完成，不做二次确认，出错靠冲正”；而需求文档写“关键动作需二次确认”。
- **影响**：误存/误取/误购依赖冲正补救；冲正本身有确认，但原始操作没有。
- **建议**：至少对大额取款/购买增加确认；或保留一次点击但提供 3 秒内“撤销”提示；与需求方确认取舍并记录。

#### M-11 Safari 16.0–16.3 兼容性（中低）

- **证据**：`client/src/lib/rpc.ts` 使用 `AbortSignal.timeout(5000)`，Safari 16.4 才支持；`PHASE-1.md:590-592` 写的是 iPad Safari 16+；Playwright 只跑 Chromium。
- **影响**：部分 iPad 上所有 RPC 直接抛错，柜台不可用。
- **建议**：加 polyfill / 手动 `AbortController + setTimeout`；把兼容下限改为 16.4，或补 WebKit 测试。

#### M-12 需求 P0“日终轧账”缺失，冻结/毕业无入口（中，范围）

- **证据**：
  - `docs/requirements/海豚银行线上平台功能需求3.0.docx` 将日终轧账列为 P0；
  - `PHASE-1.md:47` 明确“本阶段不设班次、不做轧账”；
  - `PHASE-1.md:31` 将凭条、报表、盘点、贷款、学期结转列为后续；
  - `students.status` 有 `normal/frozen/graduated`，但没有修改状态的管理 RPC/UI。
- **影响**：不是代码 bug，而是**验收口径冲突**；日终现金核对、柜员交班目前只能靠 `counter/today` 汇总 + 人工。
- **建议**：与需求方确认 P0 降级并写决策记录；若必须做，至少实现“日终汇总 + 现金实盘 + 锁定当日”最小闭环。冻结/毕业建议在首批学生毕业前补管理入口。

#### M-13 根目录未跟踪的 20 人真实名册（中，隐私/仓库卫生）

- **证据**：`测试名册-20人.xlsx` 含真实姓名风格数据（林小雨、陈子涵等），未被 `.gitignore` 覆盖，也未提交；一旦误提交会进入 Git 历史。
- **建议**：移出仓库或加入 `.gitignore`；检查历史中是否已有类似文件。

#### M-14 商品成本对所有登录用户可见（中低，信息泄露）

- **证据**：`supabase/migrations/20261028000000_core_schema.sql:86` `products.cost`；RLS 只做行级过滤，学生可读 `listed` 商品，因此也可 `select cost`。
- **影响**：采购价对全体学生可见。
- **建议**：用视图/列权限只对库管/会计/教师暴露 `cost`，或把成本拆到独立表。
