## 四、问题清单

### P0（发布阻断）

**P0-1 E2E 红：离线存款被上班状态门禁挡住**

- 证据：`docker/e2e-test.sh dolphin-cloud:audit3` 输出 57 passed / 1 failed / 6 did not run；失败用例 `client/e2e/counter.spec.ts:108`「offline deposit is registered, then uploaded once online」在 `findStudent` 等待搜索框 60s 超时。
- 现场快照：页面同时显示「离线登记」和「暂时无法确认上班状态」，没有「搜索学生」。
- 链路：
  - `client/src/app/counter/index.tsx:85` 用 `if (!student && !duty.data)` 把柜台挡在 `DutyCard`；
  - `client/src/lib/duty.ts:6-31` 只有在线查询成功后才把 open duty 写入 localStorage；新浏览器上下文没有缓存；
  - `client/src/components/Duty.tsx` 在 `duty.fetchStatus === 'paused'` 时显示「暂时无法确认上班状态」。
  - 测试在 `setOffline(true)` 前只等 `networkidle`，未等「已上班」/搜索框出现；离线后 duty 查询被 React Query 暂停，`duty.data` 仍为 `undefined`。
- 影响：新设备/首次登录后网络在 duty 查询完成前断开，柜员无法进入离线登记——恰好是离线存款最需要可用的场景；同时 CI 必然红。
- 建议：
  1. 登录/上班成功即持久化 open duty，离线时用最后已知状态打开柜台；或对 `offline` 存款不要求已知 duty（服务端 `require_duty` 已对 offline 例外）；
  2. E2E 在切离线前显式等待「已上班」或搜索框，并补一条「无缓存首次离线」用例；
  3. CI 对 E2E 失败直接失败（当前脚本已如此，不要在外层包 `| tail`）。

### P1（上线前应处理）

**P1-1 备份加密是可选项，默认仍为明文，且无异地**

- `docker/bin/dolphin` 仅在设置 `BACKUP_RECIPIENT` 时用 age 加密；升级输出明确警告 `BACKUP_RECIPIENT is not set, so backups are not encrypted`。
- 已修：备份目录 `go=`/文件 600、备份/恢复审计、恢复时先清空 `/data/storage` 再 `cp -a`（挂载点修复）。
- 未修：默认不加密、无异地副本、无恢复演练记录。备份包含 auth 哈希与会话，泄露影响大。
- 建议：生产模板强制设置 recipient，启动时缺省即拒绝或显著告警；文档给出异地/离线副本与恢复演练。

**P1-2 日终轧账仍未实现**

- 需求 docx 把「日终轧账（现金实盘、锁班）」列为 P0；PHASE-1.md 明确本阶段不设班次、不做轧账。
- 现在有「上班/下班 + 下班总结 + 工资考勤」，但**没有现金实盘、长短款、锁班、次日交接**；下班总结只是交易清单。
- 这是需求范围缺口，不是实现 Bug；上线前应与校方确认是否接受「无日终」的试点范围。

**P1-3 密码策略被放宽为「8 位任意字符」，且无 IP 级限速**

- `docker/supervisord.conf` 只保留 `GOTRUE_PASSWORD_MIN_LENGTH=8`；此前要求的字母+数字已移除；`docker/smoke-test.sh` 现在明确接受 8 位纯数字。
- 随机初始密码（学生 8 位数字、员工 8 位字母数字）与 5 次/15 分钟账户锁定是好的；但用户可把密码改成 `12345678`，且锁定是按账号，攻击者可对同一账号制造 15 分钟拒绝服务，也可换 IP 绕过。
- 建议：至少恢复「字母+数字」或长度 ≥10；加 IP/设备维度限速；锁定提示不要暴露账号存在性。

**P1-4 「在此设备保存登录」存在竞态与残留缓存**

- `client/src/app/login.tsx:55` 在 `signInWithPassword` 后调用 `setSaved(data.user.id, save)` 但没有 `await`；若 Supabase 的 `SIGNED_IN` 事件在 `setSaved` 之后才写入账号，保存选择可能丢失（账号以未保存状态留下）。
- 未保存账号仍会写 `dolphin.me:<uid>` 到 localStorage（`session.tsx`），关闭浏览器后资料仍在。
- `dropClosed` 需要当前 session；没有 session 时，已注销账号可能继续留在本机列表，直到下一次登录。
- 已修：保存 → localStorage、不保存 → sessionStorage，关闭浏览器即退出；令牌不再为未保存账号落盘。

**P1-5 少数安全/隐私边角**

- `closed_logins(uuid[])` 允许任意已登录用户探测任意 UUID 是否为已注销账号（ID 不可猜，影响低）。
- `bank_report` 的学生状态只统计 normal/frozen/graduated，不含 closed；客户端用 total 相减补偿，但任何新调用方都可能算错。
- 教师可以创建/重置/停用/注销运维员——PHASE-1 §4.1/6.4 把「银行管理员管理运维员账号」写成预期，因此不算越权 Bug；若治理上不允许，需要额外限制。

## 七、部署与安全

**已加强：**

- 服务以 `dolphin` 运行（postgres 仍 root→gosu；cert-watch 因私钥 root-only 例外）；Caddy `setcap`；`/srv/www` 可读；健康检查；CSP/防嵌框/存储 `default-src 'none'; sandbox`。

**仍缺：**

- 默认备份不加密、无异地；`BACKUP_RECIPIENT` 未设置是升级实测中的真实状态。
